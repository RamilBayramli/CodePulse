# CodePulse

CodePulse — плагин для IntelliJ IDEA, который показывает, сколько времени вы проводите в редакторе, какие файлы меняете и какие действия выполняете в IDE. В одном окне можно посмотреть статистику по проектам и языкам, историю сессий, локальные коммиты и активность на GitHub.

Статистика редактора хранится локально в SQLite. Интерфейс доступен на русском и английском. По умолчанию включён экономный режим.

## Установка и первый запуск

CodePulse 1.1.2 собран для **IntelliJ IDEA 2025.3.3**. Минимальная ветка сборки — **253**. В IDEA должен быть включён встроенный плагин **GitHub**. Для вкладки **Git** нужна команда `git`, доступная из `PATH`. Для вкладки **GitHub** нужен доступ в интернет.

1. Возьмите готовый `CodePulse-1.1.2.zip`. Если у вас только исходники, сначала [соберите ZIP](#сборка-и-запуск-из-исходников).
2. В IntelliJ IDEA откройте **Settings → Plugins → ⚙ → Install Plugin from Disk…**. На Windows настройки открываются сочетанием `Ctrl+Alt+S`.
3. Выберите ZIP целиком, нажмите **OK** и перезапустите IDEA, если она предложит. Так же можно обновить предыдущую версию.
4. Откройте проект и выберите **View → Tool Windows → CodePulse**. Окно также открывается по индикатору CodePulse в строке состояния.
5. Откройте файл и поработайте в редакторе. Сбор статистики включён по умолчанию. Данные появятся при обновлении отчёта. В отчётах с фильтрами можно нажать **Обновить**.

Для готового ZIP отдельный запуск Gradle не нужен. Команды в разделе «Сборка и запуск из исходников» предназначены для разработки плагина.

## Что показывает CodePulse

| Раздел | Что в нём |
| --- | --- |
| **Обзор** | Активное время, правки, график недели, языки, файлы и последние сессии. |
| **Рабочий день** | Запуски, отладка, тестовые конфигурации, действия IDE и виды правок. |
| **Активность** | Сравнение периодов, календарь за год, распределение по часам, рекорды и сессии. |
| **Git** | Ветки, состояние рабочей копии, коммиты и изменения строк в локальном репозитории. |
| **GitHub** | Профиль, репозитории, pull requests, issues, ревью и события аккаунта. |
| **Проекты** | Поиск проектов и подробности по времени, языкам и файлам каждого проекта. |
| **Языки** | Доля времени и правок по языкам. |
| **История** | Сессии за выбранный период и проект, включая время просмотра и редактирования. |
| **Достижения** | Вехи и серии по накопленной активности. |
| **Экспорт** | Сохранение отчёта за выбранный период и проект. |
| **Настройки** | Сбор данных, исключения, язык, экономный режим и операции с базой. |
| **Ресурсы** | Буфер, очередь записи, время запроса и сведения о памяти IDEA. |

В отчётах с фильтрами можно выбрать проект и период. Для своего периода введите обе даты в формате `ГГГГ-ММ-ДД`. История ограничена последними 250 сессиями в выбранном диапазоне. Полная история доступна через экспорт.

## Что учитывается

- Боковая навигация, карточки показателей, графики, подробный «Рабочий день» и раздел «Ресурсы». Поиск проектов и фильтры периода и проекта.
- Русский и английский интерфейс: **Настройки → Язык интерфейса → Применить настройки**, без перезапуска IDEA.
- Счётчики фактических запусков, отладки и распознанных тестовых конфигураций; время процессов и ненулевые коды выхода. Команды поиска, навигации, сборки, рефакторинга, форматирования, копирования, вставки, отмены, автодополнения, работы с Git и переключения файлов.
- Git: ветка, upstream, ahead/behind, изменения в рабочем дереве, локальные ветки, история коммитов, добавленные/удалённые строки, авторы и активные дни. Можно выбрать папку репозитория, период и свои коммиты по `git config user.email`.
- GitHub: профиль, репозитории, звёзды, форки, PR, принятые PR, issues, PR с вашим ревью и лента событий, включая push, комментарии и релизы.

Новые счётчики действий начинают собираться после установки 1.1. Команды означают вызов действия IDE, а не успешное завершение операции. Запуск тестовой конфигурации — не число тестов; Gradle/Maven-запуски, тип которых не раскрывает тесты, относятся к обычным запускам. Время процессов считается отдельно от активного времени. Ненулевой код выхода может означать ручную остановку.

## Локальный Git

1. Откройте **CodePulse → Git**. По умолчанию указана папка текущего проекта. Если репозиторий находится в другой папке, выберите его через **Обзор…**.
2. Выберите период и нажмите **Загрузить данные Git**.
3. Выберите **Мои коммиты** для фильтра по локальному `git config user.email` или **Все авторы**. В пустом репозитории история появится после первого коммита.

CodePulse читает локальные данные. Чтобы увидеть изменения на сервере в показателях ahead/behind, сначала обновите ссылки удалённой ветки обычной командой Git fetch в IDEA.

## Подключение GitHub

На вкладке **GitHub** нажмите **Подключить аккаунт GitHub**. В настройках IDEA нажмите **+ → Log In via GitHub**, войдите в браузере и закройте настройки. Если аккаунтов несколько, выберите нужный в списке. Ранее настроенный режим с именем пользователя и токеном также поддерживается.

Данные запрашиваются при открытии вкладки, смене аккаунта или периода и по кнопке **Обновить**. Интерфейс показывает время последнего обновления, а недоступные или неполные счётчики обозначает прочерком. Запросы выполняются напрямую к `api.github.com`. Приватные данные видны в пределах прав аккаунта.

По [документации GitHub Events API](https://docs.github.com/en/rest/activity/events) лента ограничена 300 событиями за последние 30 дней и может запаздывать. Она независима от фильтра периода для PR/issues. Число событий push не равно числу коммитов. PR и issues фильтруются по созданию, принятые/закрытые — по завершению, PR с ревью — по дате создания PR. Загружается до 100 недавно обновлённых собственных репозиториев; это не полная выгрузка большого аккаунта.

## Расход ресурсов

По умолчанию включён **Экономный режим**. Интерфейс использует Swing без Chromium/JCEF и без анимационного цикла. Скрытые отчёты не обновляются, на экране хранится один локальный отчёт. SQLite-запросы, Git и HTTP выполняются вне потока интерфейса; интеграции не блокируют запись статистики.

- Запись счётчиков раз в 15 секунд, обновление открытого отчёта раз в 30 секунд. Обычный режим: 5 и 12 секунд соответственно.
- Буфер ограничен 2048 группами редактора и 512 группами действий. При переполнении из-за проблем с диском новые группы пропускаются, в интерфейсе появляется предупреждение. Тексты документов не удерживаются в буфере.
- Очередь базы ограничена 16 задачами, интеграций — 4. Рабочие потоки завершаются после простоя. Слушатели проекта освобождаются при его закрытии.
- Кеш SQLite — 2 МиБ на соединение, временные сортировки разрешены на диске. На экране до 250 сессий/файлов и 8784 часовых групп. Общие суммы остаются полными; список и записи о рекордах помечены при ограничении. Полные экспорты запрашиваются отдельно и для очень большой истории могут потребовать больше памяти.
- Git запускается только по кнопке: до 500 последних коммитов по локальным ссылкам, до 2 МиБ вывода одной команды, таймаут 12 секунд на команду. Никакого фонового fetch или обхода вложенных репозиториев. При ограничении суммы относятся к показанной выборке. Ahead/behind зависит от свежести локальных remote-tracking refs.
- Автообновление GitHub работает только на открытой вкладке. В экономном режиме с подключённым аккаунтом интервал составляет две минуты, в обычном — одну, для публичного режима — 15 минут. При ограничении GitHub следующий запрос откладывается. Ответ ограничен 1 МиБ. Результаты Git/GitHub не записываются в локальную базу и не входят в экспорт статистики редактора.
- В экономном режиме замены более 1 048 576 единиц UTF-16 учитываются как событие без тяжёлого подсчёта строк и символов. Число таких событий видно в «Рабочем дне».

Раздел «Ресурсы» показывает размер очередей и время последней задачи базы. Значения heap относятся ко всей IDEA: они не являются измерением памяти отдельно для плагина.

## Сборка и запуск из исходников

Клонируйте репозиторий или распакуйте исходники. Для сборки понадобится **JDK 21**. В IntelliJ IDEA выберите его в настройках Gradle JVM. Если собираете из терминала, укажите путь к JDK в `JAVA_HOME` и перейдите в корень репозитория.

```powershell
.\gradlew.bat test buildPlugin
```

ZIP появится в `build/distributions`. Для проверки совместимости и запуска отдельного тестового экземпляра IDEA используйте эти команды.

```powershell
.\gradlew.bat verifyPlugin
.\gradlew.bat runIde
```

На macOS и Linux используйте `./gradlew`. По умолчанию Gradle загружает IntelliJ IDEA 2025.3.3. Для сборки с уже установленной IDEA укажите путь к ней. Например, в PowerShell команда выглядит так.

```powershell
.\gradlew.bat '-Pcodepulse.idePath=C:\Program Files\JetBrains\IntelliJIdea2025.3' test buildPlugin
```

`runIde` открывает отдельную IDEA с тестовыми настройками. В ней нужно открыть проект, чтобы начать сбор активности. Исходники находятся в `src/main`, тесты — в `src/test`, настройки сборки — в `build.gradle.kts`.

## Как считается активность

- Активное время состоит из просмотра и редактирования в сфокусированном редакторе. Последние 30 секунд после изменения считаются редактированием до переключения файла или начала бездействия. Порог бездействия по умолчанию составляет 5 минут.
- После перехода в другой проект, потери фокуса или бездействия следующая активность начинает новую сессию. Статистика записывается примерно каждые 15 секунд в экономном режиме и каждые 5 секунд в обычном. При аварийном завершении может потеряться последний незаписанный интервал.
- Добавленные и удалённые строки рассчитываются по изменению числа переносов строк в событии. Изменённые строки оцениваются по затронутым фрагментам, поэтому несколько правок одной строки учитываются несколько раз. Если IDEA не раскрывает источник изменения, событие попадает в **Other edits**.
- В **Settings** можно исключить проекты, каталоги и файлы. Указывайте по одному правилу на строку. Например, `build` для каталога, `**/*.min.js` для файлов и `My Project` для проекта.

## Экспорт и хранение данных

В разделе **Экспорт** выберите проект, период и формат, затем нажмите **Сохранить отчёт…**. PDF подходит для чтения и печати, HTML открывается в браузере, CSV предназначен для таблиц, а JSON — для обработки программами. CSV сохраняется в UTF-8 с BOM и строкой-разделителем для Excel.

База хранит время, пути, языки и числовые счётчики. Настройки сохраняются локально в `options/codepulse.xml` в каталоге конфигурации IDEA. Учётные данные GitHub берутся из хранилища паролей IDE. Статистика Git и GitHub остаётся отдельной от локальных отчётов редактора.

В **Настройках** кнопка **Резервная копия…** сохраняет снимок базы SQLite. **Восстановить базу…** заменяет текущую статистику выбранным снимком после подтверждения. **Сбросить статистику…** удаляет накопленные записи. Чтобы временно остановить сбор, отключите **Включить сбор статистики** и нажмите **Применить настройки**.

## Если что-то не работает

| Что видно | Что сделать |
| --- | --- |
| CodePulse не появился | Проверьте **Settings → Plugins → Installed**. CodePulse и встроенный GitHub должны быть включены. Перезапустите IDEA после установки и откройте проект. |
| Плагин есть, но время равно нулю | Проверьте, включён ли сбор статистики и не исключён ли проект. Поработайте в редакторе и дождитесь записи. |
| На вкладке Git нет коммитов | Проверьте папку и период. Выберите **Все авторы**, если локальный email отличается от email в коммитах. |
| На вкладке GitHub нет данных | Подключите аккаунт в IDEA и проверьте его выбор. Прочерк означает, что счётчик недоступен или ответ неполный. При лимите API ориентируйтесь на время следующей попытки. |
| `Permission denied (publickey)` при push | Проверьте SSH-ключ Git или настройте HTTPS-адрес репозитория. Вход в CodePulse используется для чтения статистики GitHub. [Устранение ошибки SSH](https://docs.github.com/en/authentication/troubleshooting-ssh/error-permission-denied-publickey) |
